# RD v1.0 RC — Windows 성능 측정

2026-10-15, Windows 11 개발 노트북. 실행 중인 사용자 프로젝트 대신 스크립트가 생성한 **로컬 bare Git 저장소와 100개 독립 Clone**으로 검사했습니다. 측정 스크립트: `scripts/bench-scale.ps1`. 모든 저장소는 변경되지 않은 `main` 브랜치에서 `manual` 모드로 구성했습니다.

| 작업 | 저장소 수 | 수정 전 v0.4 (ms) | v1.0 RC (ms) | 개선 |
| --- | ---: | ---: | ---: | ---: |
| check | 10 | 4,663 | 3,368 | 약 28% 단축 |
| check | 50 | 23,185 | 19,344 | 약 17% 단축 |
| check | 100 | 48,359 | 38,072 | 약 21% 단축 |

CLI `list` 명령은 매우 짧게 실행되어 메모리 표본 확보에 실패하기도 했습니다. **100개 저장소 `check` 검사 과정에서 관측한 RD Agent 프로세스 Working Set 최대치는 약 5.38MB**였습니다(기존 버전 4.95MB). 측정 대상은 해당 Agent 프로세스이며, Git 자식 프로세스나 전체 시스템 메모리는 포함하지 않습니다.

## 해석과 한계

- 두 버전은 동일한 Windows 노트북에서 같은 유형의 로컬 테스트 저장소로 측정했지만 각각 독립 실행한 **1회 측정**입니다. 재실행 시 저장 장치 캐시와 시스템 부하로 값이 달라집니다.
- 테스트는 원격 네트워크 지연, 100개 서로 다른 GitHub 프로젝트, 자격 증명 재요청 상황을 재현하지 않습니다.
- 트레이의 장시간 유휴 CPU/RAM, 관리 UI의 WebView2 프로세스 합산 메모리, 설치 이후 업데이트 절차는 **아직 별도 검증이 필요합니다**.
- 안전성 검증을 줄이지 않고 `operation_in_progress`에서 8회 반복하던 Git 경로 조회를 단일 Git 호출로 통합했습니다.
- 보안 보호를 우회하거나 기존 작업 폴더를 수정하지 않고 생성된 임시 폴더는 테스트 종료 시 정리합니다.
